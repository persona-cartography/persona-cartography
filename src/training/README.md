# `src/training`

Trusted, reusable infrastructure for producing persona-bearing LoRA adapters.

The **canonical** training method is **paired-DPO**. Other methods (the legacy
Inference→Editing→SFT pipeline, and older DPO variants) are historical and
migrate only when needed.

## Contents

| Path | What it is | Status |
|------|------------|--------|
| `paired_dpo/pairing.py` | Pure functions to build paired `(chosen, rejected)` DPO datasets by joining amplifier- and suppressor-teacher distillations on `prompt`. Unit-tested. | **Available** (Slice 1a) |
| `oct_adapter.py` | Thin wrapper over the external OpenCharacterTraining (`character.*`) library — constitution install + teacher/student distillation — so scripts never import `character.*` directly. | Slice 1a.2 |
| `legacy_persona_pipeline/` | Older Inference→Editing→SFT path (`generation`, `trait_amplification`, `sft`). | Future slice |

The runnable entrypoints that drive this infra live in
`scripts/training/ocean_paired_dpo/`.

## Why paired-DPO is wrapped, not reimplemented

The paired-DPO pipeline delegates teacher/student generation and DPO/SFT
training to the external **OpenCharacterTraining** library. `src/training`
holds only the pieces worth owning and testing (the dataset-pairing join, and —
later — a clean adapter seam over OCT). The heavy GPU/vLLM orchestration stays
in `scripts/`.

## Method name mapping

HuggingFace monorepo paths and historical scripts use opaque method
identifiers. In the clean `src/` + `scripts/` layer we use descriptive names;
the monorepo path strings keep the historical identifiers because those
artifacts are immutable.

| Monorepo identifier | Clean name | Notes |
|---------------------|------------|-------|
| `ocean_const_paired_dpo` | paired-DPO | Canonical method: teacher generates both an amplifying and a suppressing response per prompt; the two are paired as (chosen, rejected). |
| `vanton4` | (single-teacher distillation) | Predecessor distillation run; source of the per-direction teacher responses that paired-DPO joins. |
| `v4`, reversed-DPO | (other DPO variants) | Compared in the paper's training-methods appendix; deferred — migrate when needed. |

> The `vanton4` name appears in the paper only in `% Data:` / `% Generated by:`
> provenance comments, never in prose.
