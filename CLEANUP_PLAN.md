# Plan: Migrate `*_dev/` → `src/` + `scripts/`, slice by slice

## Context

The repo currently has a stable layer (`src/`, `scripts/`) and an active-work layer (`src_dev/`, `scripts_dev/`). The stable layer is mostly empty: only `src/utils/` is actively used (LoRA arithmetic — battle-tested, 17+ import sites). `src/inference/` and `src/lora_pipeline_persona_shattering/` are orphaned abstract-base stubs. `scripts/` does not exist yet. All real code — 20 packages in `src_dev/`, 27 dirs in `scripts_dev/` — lives in the dev layer.

The paper (Sections 3–4 + heavy appendices) depends on ~21 figure scripts and a handful of eval/training pipelines. To make the research reproducible and to position the project for replication on other model families, we want a clean `src/` (reusable library code) and `scripts/` (curated, runnable end-to-end entrypoints) layer that is a strict superset of what the paper needs, with cleaner organisation and (some) consolidation of obvious duplication.

**Goals:**
- A reader with HF monorepo data can run `scripts/figures/<...>.py` and regenerate any paper figure.
- A reader with compute can run `scripts/training/<...>.py` → `scripts/evals/<...>.py` → `scripts/figures/<...>.py` end-to-end.
- `src/` is reusable infrastructure that extends cleanly to new model families and new traits.
- `*_dev/` keeps working as the active workspace; team members' existing imports do not break.

**Non-goals (for this plan):**
- Cleaning up the HF monorepo (separate effort, but the new `src/` must read the existing layout).
- Pruning `*_dev/` code (others still depend on it).
- Building a top-level orchestrator (`make reproduce-paper`). Individual scripts only.

---

## Migration principles

1. **Vertical slices, one paper section at a time.** Each slice is independently end-to-end runnable (training-optional, figures mandatory) before the next slice begins.
2. **Migrate, don't fork.** Copy from `*_dev/` into `src/`+`scripts/`, then refactor in place. Originals stay; team members keep their imports.
3. **Refactor opportunistically.** Consolidate near-duplicate scripts (>80% shared logic) into one parameterised version. Do not consolidate when scripts diverge meaningfully — and keep the `% Generated by:` LaTeX comments updated when names change.
4. **Smoke test + figure regeneration is enough for each slice's "done"**, with full end-to-end re-run flagged as a TODO. Full re-runs will happen when we replicate the research on other model families anyway.
5. **`src/utils/` stays; orphaned stubs in `src/` get deleted** when their replacement lands (interfaces are designed once we know how the implementations actually compose).
6. **Cost discipline.** Plumbing work (`--dry-run`, import checks, CLI smoke tests) on a cheaper model per `CLAUDE.md`.

## Layout

Top-level structure that we'll grow into:

```
src/
  utils/                       # already exists, keep as-is
  datasets/                    # canonical dataset loading/normalization (from src_dev/datasets)
  generation/                  # response generation against base+LoRA (from src_dev/inference)
  trait_amplification/         # rewrite/edit responses (from src_dev/lora_pipeline_persona_shattering/editing)
  training/                    # LoRA training (from src_dev/lora_pipeline_persona_shattering/training)
  evals/                       # trait/MMLU/judge sweeps (from src_dev/evals)
  persona_metrics/             # per-response trait scoring
  visualisations/              # PAPER_FIGURES_DIR, shared plotting helpers
  factor_analysis/             # unsupervised (later slice)
scripts/
  training/                    # one script per (training method × OCEAN±) where applicable
  evals/                       # trait_sweep, mmlu_sweep, judge_sweep entrypoints
  figures/                     # paper figure scripts, one per \includegraphics target
  unsupervised/                # FA pipeline orchestration
  combinations/                # LoRA arithmetic experiments
```

**Taxonomy notes:**
- `src_dev/inference/` → `src/generation/` (clearer to external readers; "inference" is overloaded with model-serving).
- `src_dev/lora_pipeline_persona_shattering/editing/` → `src/trait_amplification/` (says what it actually does — rewriting responses with a stronger LLM to amplify a trait).
- Other names (`training`, `evals`, `datasets`, `persona_metrics`) stay.
- Final taxonomy decisions are made *per slice* when we actually pick up that package. We commit to the names above as a working proposal, not a frozen contract.

**Naming cleanup we should do during migration (open to feedback):** The HF monorepo paths and figure scripts use `vanton4_paired_dpo` / `vanton4` as method identifiers. These names don't appear in the paper text (need to verify), and they're meaningless to external readers. Propose: rename to something descriptive (`paired_dpo` / `vanilla_dpo`) in `scripts/` + `src/`, with a mapping table in `src/training/README.md` documenting the historical names. The HF monorepo paths stay (those are immutable artifacts).

## Slice 1 (FIRST): Supervised — OCEAN trait/MMLU/judge scaling (figures-only)

**Paper coverage:** Section 3 main scaling figures + Appendix F (paired-DPO sweeps for all 10 OCEAN± adapters).

**Scope:**
- Migrate the 4 paired-DPO figure scripts + their direct `src_dev/` dependencies.
- *Do NOT* migrate training (`run_oct_pipeline.py`) yet — that's Slice 2.
- *Do NOT* consolidate the 3 `paper_appendix_paired_dpo_{trait,mmlu,judge}.py` files yet — discuss case-by-case (see below).

**Files to migrate (paths relative to repo root):**

Library code → `src/`:
- `src_dev/utils/hf_hub.py` → `src/utils/hf_hub.py` (already heavily depended on; promote it).
- `src_dev/evals/personality/analyze_results.py` → `src/evals/personality/analyze_results.py` (BIG_FIVE_COLORS, Wilson/BCa CI, logprob/MMLU/judge parsers — heavy reuse across all 4 figure scripts).
- `src_dev/visualisations/__init__.py` → `src/visualisations/__init__.py` (defines `PAPER_FIGURES_DIR`, the canonical figure output path).
- `src_dev/visualisations/ocean_spider.py` → `src/visualisations/ocean_spider.py` (used by the banner figure; small shared helper).

Scripts → `scripts/figures/`:
- `src_dev/visualisations/paper_main_o_plus_scaling.py` → `scripts/figures/main_ocean_scaling.py`
- `src_dev/visualisations/paper_appendix_paired_dpo_trait.py` → `scripts/figures/appendix_paired_dpo_trait.py`
- `src_dev/visualisations/paper_appendix_paired_dpo_mmlu.py` → `scripts/figures/appendix_paired_dpo_mmlu.py`
- `src_dev/visualisations/paper_appendix_paired_dpo_judge.py` → `scripts/figures/appendix_paired_dpo_judge.py`

For each migrated script:
- Update local imports to point to `src.*` instead of `src_dev.*`.
- Preserve the `PAPER_FIGURES = [...]` declaration.
- Update the corresponding `% Generated by:` comments in `paper/sections/*.tex` and `paper/figures/MANIFEST.md`.
- Add a module-level docstring explaining what HF monorepo data the script reads and what figure(s) it produces.

**Open question — consolidate the 3 paired-DPO appendix scripts?**
- They share: HF path resolution, OCEAN trait/direction iteration, output naming.
- They differ: metric extraction (trait logprobs vs MMLU breakdown vs judge JSONL), plot layout per metric, error-bar method (Wilson vs BCa).
- Recommendation: keep as 3 files. Extract shared helpers (HF path resolution, OCEAN iteration) into `src/evals/personality/paired_dpo_paths.py`. The metric-specific plotting stays per-script — that's where divergence is real.

**Critical-file shortlist (Slice 1):**
- New: `src/evals/personality/analyze_results.py`, `src/utils/hf_hub.py`, `src/visualisations/__init__.py`, `scripts/figures/{main_ocean_scaling,appendix_paired_dpo_*}.py`.
- Edits: `paper/figures/MANIFEST.md`, `paper/sections/{supervised,appendices/*}.tex` (just `% Generated by:` updates).
- Cleanup: delete `src/inference/`, `src/lora_pipeline_persona_shattering/` orphan stubs once we're sure no one imports them (grep confirmed nothing does).
